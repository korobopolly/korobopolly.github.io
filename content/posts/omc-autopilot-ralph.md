## 자동화된 개발의 시작

OMC의 가장 강력한 기능은 개발 과정 전체를 자동화하는 실행 모드들입니다. Autopilot은 아이디어에서 완성된 코드까지의 전체 여정을 자동으로 처리하고, Ralph는 작업이 완벽하게 완료될 때까지 반복 검증하며, Ultrawork는 병렬 실행으로 속도를 극대화하고, Ecomode는 비용을 최적화합니다.

이러한 모드들은 각각의 강점을 가지고 있으며, 작업의 성격에 따라 적절히 선택하면 개발 생산성을 획기적으로 향상시킬 수 있습니다.

## Autopilot - 완전 자동 개발

Autopilot은 사용자의 요청을 받아 분석부터 구현, 테스트, 검증까지 전체 개발 사이클을 자동으로 수행합니다.

### 기본 사용법

```
/autopilot "JWT 기반 사용자 인증 API를 만들어줘"
```

단 한 줄의 명령으로 Autopilot은 다음 워크플로우를 자동 실행합니다.

### 자동 워크플로우

1. **요구사항 분석** (analyst 에이전트)
   - 사용자 요청을 명확한 요구사항으로 변환
   - 숨겨진 제약사항과 수용 기준 도출
   - 기술적 선택지와 트레이드오프 분석

2. **코드베이스 탐색** (explore 에이전트)
   - 관련 파일과 함수 탐색
   - 기존 패턴과 컨벤션 파악
   - 의존성과 아키텍처 이해

3. **계획 수립** (planner 에이전트)
   - 작업을 순차적 단계로 분해
   - 각 단계의 검증 기준 정의
   - 리스크와 블로커 식별

4. **구현** (executor 에이전트)
   - 계획에 따른 코드 작성
   - 기존 코드와의 일관성 유지
   - 필요한 헬퍼와 유틸리티 생성

5. **테스트 작성** (test-engineer 에이전트)
   - 단위 테스트와 통합 테스트 작성
   - 엣지 케이스와 에러 시나리오 커버
   - 테스트 실행과 결과 확인

6. **검증** (verifier 에이전트)
   - 모든 요구사항 충족 확인
   - 테스트 통과 여부 검증
   - 코드 품질과 보안 검토

### 실전 예시

```
/autopilot "블로그 포스트 CRUD API를 Express로 구현하고, PostgreSQL 연동, 입력 검증, 에러 핸들링 포함"
```

Autopilot은 이 요청으로부터:
- Express 라우터 구조 설계
- PostgreSQL 스키마 및 마이그레이션 생성
- CRUD 엔드포인트 구현
- Joi 또는 Zod로 입력 검증
- 에러 미들웨어 구현
- 단위 및 통합 테스트 작성
- API 문서 생성

모든 과정을 자동으로 수행합니다.

## Ralph - 자기 참조 검증 루프

Ralph는 작업이 완벽하게 완료될 때까지 실행과 검증을 반복하는 모드입니다. 단순히 코드를 작성하는 것이 아니라, 결과가 기준을 충족할 때까지 자동으로 개선합니다.

### 기본 사용법

```
/ralph "모든 단위 테스트가 통과하고 커버리지가 80% 이상이 될 때까지 버그를 수정해"
```

### 자기 참조 루프 메커니즘

Ralph의 실행 사이클은 다음과 같습니다:

1. **작업 실행**
   - 지정된 작업 수행 (버그 수정, 기능 추가 등)
   - 코드 변경 및 테스트 실행

2. **결과 검증** (verifier 에이전트)
   - 테스트 통과 여부 확인
   - 커버리지, 성능 등 메트릭 측정
   - 요구사항 충족 여부 판단

3. **Architect 검토** (architect 에이전트)
   - 코드 품질과 아키텍처 일관성 검토
   - 장기적 유지보수성 평가
   - 개선 필요 사항 식별

4. **재시도 또는 완료**
   - 검증 실패 시: 문제점 분석 후 1단계로 복귀
   - 검증 성공 시: 작업 완료
   - max_iterations 도달 시: 실패 보고

### 실전 예시

```
/ralph "API 응답 시간이 100ms 이하가 될 때까지 성능 최적화"
```

Ralph는:
- 첫 시도: 데이터베이스 쿼리 최적화
- 검증: 응답 시간 150ms - 실패
- 두 번째 시도: 인덱스 추가
- 검증: 응답 시간 120ms - 실패
- 세 번째 시도: Redis 캐싱 추가
- 검증: 응답 시간 80ms - 성공

각 반복마다 architect가 접근 방식을 검토하고, verifier가 결과를 측정하며, 목표 달성까지 자동으로 개선합니다.

## Ultrawork - 병렬 실행 최적화

Ultrawork는 여러 에이전트를 동시에 실행하여 처리 속도를 극대화합니다.

### 기본 사용법

```
/ultrawork "프로젝트 전체를 TypeScript strict 모드로 마이그레이션"
```

### 병렬 처리 전략

Ultrawork는 다음 방식으로 작업을 분산합니다:

1. **작업 분해**
   - 독립적으로 실행 가능한 하위 작업으로 분할
   - 파일 또는 모듈 단위로 소유권 할당

2. **파일 소유권 관리**
   - 각 에이전트가 특정 파일 세트를 전담
   - 동시 수정으로 인한 충돌 방지
   - 의존성이 있는 파일은 순차 처리

3. **병렬 실행**
   - 여러 executor 에이전트를 동시 실행
   - 각 에이전트는 할당된 파일만 수정
   - 진행 상황을 실시간 모니터링

4. **결과 통합**
   - 모든 에이전트의 작업 완료 대기
   - 통합 테스트 실행
   - 최종 검증

### 성능 비교

일반 모드:
- 100개 파일 마이그레이션: 약 50분

Ultrawork 모드:
- 100개 파일 마이그레이션: 약 12분 (4배 빠름)

## Ecomode - 비용 최적화

Ecomode는 토큰 비용을 절감하면서도 작업 품질을 유지하는 모드입니다.

### 기본 사용법

```
/ecomode
```

활성화 후 모든 에이전트 호출에 자동 적용됩니다.

### 모델 다운그레이드 전략

Ecomode는 작업 복잡도에 따라 모델을 자동 선택합니다:

- **opus → sonnet**: 아키텍처 설계, 심층 분석
- **sonnet → haiku**: 단순 구현, 리뷰, 검색

품질이 중요한 작업(보안 리뷰, 복잡한 리팩토링)은 여전히 상위 모델을 사용하지만, 대부분의 작업은 하위 모델로도 충분한 품질을 유지합니다.

### 비용 절감 효과

일반 모드:
- 중형 프로젝트 리팩토링: 약 $15

Ecomode:
- 동일 작업: 약 $6 (60% 절감)

## 모드 선택 가이드

작업 유형에 따른 최적 모드 선택:

### 새 기능 구현
**권장: Autopilot**
- 요구사항 분석부터 검증까지 자동화
- 테스트 포함 완전한 구현
- 예: "결제 시스템 통합"

### 반복 작업 또는 버그 수정
**권장: Ralph**
- 목표 달성까지 자동 반복
- 품질 기준 충족 보장
- 예: "모든 린트 에러 제거"

### 대규모 리팩토링
**권장: Ultrawork**
- 병렬 처리로 시간 단축
- 대량 파일 동시 수정
- 예: "전체 코드베이스 ESLint 적용"

### 비용 민감 프로젝트
**권장: Ecomode**
- 모든 모드와 조합 가능
- 품질 유지하며 비용 절감
- 예: "/ecomode /autopilot ..."

### 복합 모드
여러 모드를 조합할 수도 있습니다:

```
/ecomode /ultrawork "100개 컴포넌트를 Tailwind CSS로 마이그레이션"
```

경제적인 모델로 병렬 실행하여 빠르고 저렴하게 대규모 작업을 완료합니다.

## 마무리

OMC의 실행 모드들은 개발 과정의 서로 다른 측면을 최적화합니다. Autopilot은 완전 자동화를, Ralph는 품질 보장을, Ultrawork는 속도를, Ecomode는 비용 효율을 제공합니다.

다음 글에서는 Team과 Pipeline 모드를 통해 여러 AI 에이전트가 협업하는 워크플로우를 구축하는 방법을 살펴보겠습니다.
